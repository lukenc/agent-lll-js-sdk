# 事故复盘报告

按下面五段写，缺的段落写"暂无"而不是删掉 —— 复盘的价值在于暴露空白。

## 1. 摘要

一句话说清：什么时间、什么系统、什么现象、影响多少用户。

## 2. 时间线

按 `HH:MM` 逐条列出：告警触发 → 介入 → 定位 → 缓解 → 恢复 → 确认。
每条注明是谁做的。

## 3. 影响面

受影响的功能、请求量/用户数量级、有没有数据损坏或丢失。

## 4. 根因

区分**触发条件**（这次为什么发生）与**根本原因**（为什么这个条件能造成故障）。
只写触发条件的复盘是没做完的复盘。

## 5. 修复与预防

- 已做的止血措施
- 待办的根因修复（带负责人）
- 能让同类问题下次自动暴露的检测项
